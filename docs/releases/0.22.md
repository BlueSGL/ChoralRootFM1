ChoralRoot 0.22 (in progress)

- **Chord numerals in Key Mode.** A new setting, **Numerals**, on the KEY layer's second page (hold KEY, turn SELECT,
  KNOB 4). It is off until you turn it on. With Key Mode on, the Chord view then shows the Roman numeral of the chord
  you are playing, in blue above the chord's name: in C major `I` for C, `V` for G, `vi` for Am. Capitals are chords
  with a major third, small letters chords with a minor third. The numeral is the degree you played: Transpose is
  left out, so the tonic chord reads `I` at any Transpose, while the name shows the chord you hear. Hold SAVE to
  keep the setting. Nothing you hear changes.

## Dual Core: Off by itself after a crash, the regulator at 1.50 V

Some FM-1s crash with both cores running (issue #9 here; fm1-x0x #10 and #21 in Charles Vestal's firmware, where
fc79 and zednaked measured it): at the chip's speed and the voltage the boot loader leaves, the memory misreads now
and then with two cores busy, and that can hit the first core, which no check on the second core can catch. Until
0.21 such a crash restarted the FM-1 with Dual Core still On, so it crashed again: a restart loop that only SAFE MODE
broke. Two changes:

- **With Dual Core On, the regulator (VDC14) now goes to 1.50 V** before the second core starts, instead of 1.45 V.
  Every report agrees it is the voltage that matters: at 1.50 V the affected units ran clean where 1.45 V still
  crashed; fm1-x0x ships 1.50 V since 1.0.7, the chip's data sheet allows 1.55 V, and the stock M-VAVE firmware runs
  the unit at 1.60 V. The core voltage stays at 1.35 V. With Dual Core Off (the default) nothing changes.
- **If the FM-1 crashes, hangs or gives the second core up with Dual Core On, it turns the option Off and saves it.**
  After the restart the screen says `dual core off: crash` (or `hang`, `gave up`), Options > Dual Core reads Off with
  the reason on the line under it (`off after a crash on 2 cores`), and the FM-1 stays on one core over power cycles
  until you turn it On again. The Geek Out view says `c1 off · after a crash`; `fm1_install.py --debug` adds `c1_bar`.
  The second core is also held first thing at every reset, before the memory is cleared.

If your FM-1 turns Dual Core Off by itself, please tell us (with `fm1_install.py --debug`): it means this unit does
not run both cores at 1.50 V either, and that is worth knowing.

## Going back to 0.21

0.21 and the versions before it have no Numerals setting and ignore it; nothing else is lost or reset. If you hold
SAVE while on the older version, Numerals is off when you come back to 0.22. Dual Core is read the same way by both
(a 0.22 that turned it Off saved Off, which 0.21 honours); 0.21 raises the regulator to 1.45 V again with it On.
